Фильм **7:20**, H.264/yuv420p, 1920×1080, 20 кадров/с, без звука. Каждая последовательность сканов идёт при нормальной скорости **1×**, исходные 10 Гц: один скан показывается два кадра MP4. Титры добавляют время, но не замедляют последовательности. Нет интерполяции облаков, выдуманных детекций или декоративных моделей человека. Камера смотрит вперёд из положения лидара; зелёный габарит восстановлен по измерениям, фиолетовый экстраполирован, красные рамки — СТОП, жёлтые — предупреждение. Цвет точек означает высоту. Рассеяние — счётчик, не нарисованные мишени и не подтверждённый класс пыли.

## Данные и смысл проверки

1. **falcon_test.zst — реальная запись**: статичный поезд, движущийся человек, проверены все 4443 скана. В фильме три непрерывных фрагмента: кадры 0–300, 2200–2400, 3800–4000, всего 703 скана. Первое native-совпадение с автоматической траекторией: **256,56 м при t=4,5 с**, примерно **00:10,5 фильма**. Рамка показывает свою оценку дистанции, поэтому число на ней может отличаться от траектории. Прежние 258,5 м получены в другом запуске: это не гарантированная дальность для любого препятствия. Первое СТОП — 257,36 м, t=5,3 с. Отдельно показан один и тот же кадр 2255 до/после исправления: WARNING→STOP.
2. **cloud_with_fake_obj.zst — квалификационная запись с искусственными объектами**, не new_synth. Полностью проверено 1510 кадров; фильм показывает 200 последовательных кадров локального времени 3,0–22,9 с. Архив на ПК восстановлен, SHA-256 совпадает с публичным оригиналом, весь zstd-поток проходит проверку.
3. **new_synth_data.zst — новые синтетические сцены организаторов**: платформа 386, стрелка 736, тоннель 545. Показаны все 1667 сканов. Цель — совместимость сенсора/осей, геометрия пути, фильтр и работа ROS/RViz на полных записях. Доступных независимых классовых и аэрозольных меток нет: выходы модели не являются разметкой. Наличие dust-флага не доказывает настоящий аэрозоль.
4. **Наши инъекции в реальный фон Falcon**: человек, ящики 0,5 и 0,3 м, модель аэрозоля; 17 дальностей **60, 90, 100, 120, 150, 175, 180, 190, 200, 215, 220, 230, 250, 260, 270, 280, 300 м**. Цель — диагностировать дальность, задержку, пропуски и нежелательный СТОП. По каждому условию 30 кадров прогрева +50 с инъекцией; проценты используют все 50, включая подтверждение. В фильме одинаково показываются последние 20 из 50 кадров, 2 с на условие. Один фиксированный seed на дальность; совпадение по продольной дистанции ±4 м. В фоне может быть другой человек: его рамка не означает детекцию инъекции. Это диагностическая лестница, не независимая оценка реальной точности или доверительный интервал.

Отдельный **255-условный регрессионный протокол** использует три seed, разные фоновые окна и дополнительное поперечное сопоставление. Человек 300 м: 123/150 предупреждений, 10/150 СТОП. Эти доли нельзя смешивать с односидовой лестницей. Ящик 0,3 м на 300 м часто имеет менее одного возврата в кадре и не обнаруживается — ограничение показано, а не скрыто.

## Повторная генерация на другом ПК / в облаке

Для запуска детектора следуйте [пошаговой инструкции Docker/RViz](RUN_ON_PC_RU.md). Для воспроизведения именно этого фильма скачайте артефакты `generalization-eval` 39197603363 и `dense-organizer-eval` 39200634492 из вкладки Actions (нужен GitHub-вход для артефактов), распакуйте их в отдельные каталоги `quality` и `dense`. Публичные MP4 доступны без входа. В `quality` должны находиться `baseline`, `candidate` (включая `injection_clips`) и `holdout`; в `dense` — `qualification`, `offline`, `cab_video.json`, `tunnelguard_organizer.mp4`. Для повторного вычисления облачные workflows берут проверяемые исходники из публичной папки организаторов, без большого скачивания на Windows.

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell вместо предыдущей строки:
# .\.venv\Scripts\Activate.ps1
python -m pip install numpy pillow imageio imageio-ffmpeg
python tools/finals_comprehensive_video.py --quality quality --dense dense --web web --out result.mp4
```

Нужны интернет для первого получения FFmpeg через imageio и место для временных глав/мастера. Шрифт должен поддерживать русский язык; на Windows используется системный Segoe UI, на Linux — DejaVu Sans. При других версиях FFmpeg бинарный SHA MP4 может отличаться, а исходные сканы и главы должны совпадать. Большие архивы не включены в Git. Дополнительный `new_data.zst` из общей папки этим фильмом и тестами не покрыт.
